# Mobile camera clearance

The canvas, dashboard and pointer coordinate space retain the v1.12.30 full-screen dimensions. Background graphics can pass behind the camera; readable UI and touch targets avoid a local camera rectangle.

Apple's [layout specifications](https://developer.apple.com/design/human-interface-guidelines/layout) list the iPhone 14 as 390 x 844 logical points (1170 x 2532 pixels at 3x). Its official [dimensional drawing](https://developer.apple.com/download/files/accessories/dimensional-drawings/iphone-14.pdf), sheet 1, labels the display's active width as 64.58 mm and its camera cutout as 26.79 mm wide and 5.58 mm deep. Converting at 390 / 64.58 gives approximately 162 x 34 logical points. The UI guard adds six points of clearance; reported safe-area depth takes precedence if larger. These rounded guard dimensions are conservative layout estimates, not a browser-provided cutout contour.

In landscape, the housing occupies the middle of a side edge. Safari's legacy `window.orientation` is 90 with the camera on the left and -90 with it on the right, per Apple's [orientation documentation](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/HandlingEvents/HandlingEvents.html). The modern Screen Orientation angle uses 270 and 90 respectively. In the portrait landscape fallback, the top housing maps to the game's left edge. When orientation is unavailable, reserve both reported side-camera rectangles, never full-height strips. An iPhone-sized fallback protects the standard iPhone 14 housing if Safari exposes no inset. Browser chrome's reduction of the short axis expands the guard's span conservatively to account for an unknown screen-to-viewport offset.

Only intersecting UI components change. The chart and terminal acquire a rounded recess in their outline and clipping region; their content remains within a consistent readable column. The selected-target button stack uses its existing horizontal slide with a camera-free closed position. Target labels and custom navigation controls include the camera rectangles in their placement obstacles. Full-screen Settings and Log retain their full-width frames, with interior camera clearance for text, controls and scrolling.

CSS inset sensors, orientation events and component size/mode observers refresh the fit without changing canvas size. The web platform reports edge safe insets, not exact camera polygons or the size of expanded system activities. The iPhone 14 model is the supported baseline; larger reported depths are respected, but physical-device validation is still required for other hardware or expanded Dynamic Island activities.

The revised 1.12.31 release uses cache revision 2. The visible version stays 1.12.31, and the new service worker builds a separate shell cache from the earlier inset-viewport implementation.
